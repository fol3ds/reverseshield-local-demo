## Project fit and evidence

| Example | ReverseShield status | Evidence / boundary |
|---|---|---|
| Threat/anomaly detection | Not implemented | No runtime monitoring or threat classifier. Entropy is a measurement, not a malware verdict. |
| Software vulnerability discovery | Supporting workflow | Static ELF/PE metadata, symbols, strings and decompiler evidence help analysts investigate exposure. No automatic exploitability verdict, CVE matching or validated vulnerability detector. |
| Identity/access management | Local request protection only | Token and browser-origin checks tested; no user accounts, RBAC or enterprise identity service. |
| Incident analysis/response | Limited supporting evidence | Hashes and reports support inspection; no incident response orchestration or live containment. |
| DLP/sensitive-data discovery | Bounded supporting capability | Existing path/home-path string counts plus new sanitized export. Not endpoint DLP, universal secret detection or exfiltration blocking. |
| Recovery/data restoration | Not implemented | Copy-only transformations preserve originals; this is not backup or recovery software. |

Primary positioning: static software exposure analysis for authorized security
analysts and developers, with safe evidence sharing. Do not inflate the scope
to claim all six examples. Future hardening checks, offline CVE correlation and
isolated adapters remain roadmap items.
