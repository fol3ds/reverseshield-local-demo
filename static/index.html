Workflow / boundaries

Read Me

From application to evidence

  1. Discover a source. Choose an installed Flatpak, enter an absolute local folder/RPM/ELF path, upload ELF/RPM bytes, or choose a bundled sample.
  2. Review the preview. Select the ELF targets you need. Non-analyzable entries show their reason. Runtime dependencies are listed separately; they are not scanned.
  3. Choose tools and authorize. All available analysis tools are selected by default. Use manual selection to opt out. Missing tools and partial results remain visible.
  4. Start a job. Monitor actual tool and phase events, cancel work when needed, and reopen recent runs. No percentage estimate is invented.
  5. Inspect the evidence. Browse metadata, functions, symbols, strings, pseudocode, actual graphs, and raw commands/output. Download the full JSON, including partial results.

What comparison means

Three profiles operate on copies: two sample-only source profiles (GNU symbol removal and a demo-grade constant-blinding transformation), and binary metadata hygiene for any selected ELF. Each is followed by a fresh static analysis.

They are labelled Symbol removal applied, Demo obfuscation applied, or Binary metadata hygiene applied. None is a protection certification or a reverse-engineering resistance score.

Before and after function selections are independent. Names may disappear after stripping; the interface does not claim matching functions or equivalent behavior.

Hard boundaries

  • Targets are never executed. Dynamic analysis is disabled.
  • This is not a malware sandbox. Only submit benign files you own or are authorized to inspect.
  • Behavior is not verified before or after either transformation.
  • Unavailable pseudocode or graphs mean unavailable / not collected, not that a file is secure.
  • Displayed evidence can be capped for responsiveness; tool truncation and report limitations are shown. Use JSON for all returned evidence.
  • The page uses local assets only: no remote fonts, analysis services, or graph libraries.
