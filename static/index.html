Plain-language guide

How ReverseShield works

From a program to a report

  1. Choose a source. A bundled sample, an uploaded file, a file or folder on this computer, or (on Linux) an installed Flatpak app.
  2. Pick the files. Each program shows its type: ELF (Linux) or PE (Windows). Files that cannot be analyzed show why.
  3. Confirm and start. All installed tools run by default; choose “Let me choose” to skip some.
  4. Watch the activity log. Each tool’s messages appear live. You can cancel at any time.
  5. Read the report. It starts with plain-language findings: names, debug information, file paths and code that could be recovered. Details are in the tabs below the findings.

What the numbers mean

  • Symbol names are function and variable names left in the file. They make reverse engineering much easier.
  • Debug information can reveal source file names, line numbers and variable types.
  • Entropy runs from 0 to 8. Normal code is about 4–6; values near 8 usually mean compressed or encrypted data.
  • Imports are functions the program borrows from system libraries. They hint at what it does (files, network, crypto).
  • N/A means “not collected” (for example a tool was not installed). It never means zero.

What a comparison shows

You can apply one change to a copy and analyze it again: hide constants (demo), remove symbol names, remove debug info and build metadata, or use OLLVM on the five self-authored sample sources on Linux. The sixth hardened fixture is analysis-only. The Compare page lists what changed, what did not, and which functions still match.

These changes are demonstration-grade, not a security certificate. Ghidra may still recover program logic. OLLVM's limited QEMU driver checks do not prove general behaviour equivalence.

Hard limits

  • Host targets are never executed. The optional OLLVM sample behaviour check runs only inside a QEMU micro-VM with no disk and no network.
  • This is not a malware sandbox. Only use files you own or are allowed to inspect.
  • Changed downloadable copies are not behaviour-tested. OLLVM's QEMU comparison runs separate deterministic driver builds from five self-authored sources, not the downloadable protected ELF and not arbitrary target behaviour.
  • Missing pseudocode or graphs means “not collected”, not “secure”.
  • Long tables and graphs are shortened on screen; the downloaded JSON report has everything collected.
  • The page uses only local files: no web fonts, cloud services or tracking.
